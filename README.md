# TVH M3U Maker

TVHeadend 채널을 M3U로 만들고 Shyni에는 HLS 프록시 주소로 제공하는 FF 플러그인입니다.

## 2.1.3 · 공용 조회와 아이콘 업로드 보안

공용 채널·별칭·로고 카탈로그 접근을 개인 FF API에서 분리했습니다. 배포되는 카탈로그 전용 접근값은 `normal/catalog`의 허용된 조회만 사용할 수 있으며, 개인 재생 목록·FF 설정·DB 쓰기에는 사용할 수 없습니다. 개인 FF API 키는 저장소에 넣지 않습니다. 기존 개인 M3U 주소와 FF API 인증은 유지됩니다.

아이콘 업로드는 PNG·JPEG·GIF·WebP만 허용하고 메타데이터를 제거한 정적 PNG로 저장합니다. 파일을 최대 5MB+1바이트까지만 읽어 크기를 검사하며, 요청 전체 6MB·가로/세로 4096픽셀·동시 디코딩 2건을 제한합니다. Pillow 12.3.0 이상과 수정된 WebP 디코더가 필요합니다. 구버전 디코더는 업로드를 거부하므로 FF 이미지의 실제 라이브러리도 업데이트해야 합니다.

공용 로고 수신은 서버에만 보관하는 비공개 제출 전용 키와 POST 요청만 허용합니다. 제출 키는 GitHub나 플러그인 기본값으로 배포하지 않습니다. 개인 FF 키를 원격 수신 서버에 보내지 않습니다. 이미지 검증에 실패하면 전체 성공 업로드 한도를 차감하지 않으며, 접속 주소별 시도 제한과 전체 일일/저장 용량 제한을 적용합니다. 프록시 환경에서는 여러 사용자가 같은 접속 주소 제한을 공유할 수 있습니다.

공개 제출은 기존 카탈로그 아이콘을 덮어쓰지 않습니다. 기존 아이콘의 교체는 해당 서버의 로그인된 관리자 업로드로 처리합니다. 각자의 FF에서 로그인한 뒤 올린 아이콘은 해당 FF에 정상 저장되며, 공용 전송 실패가 로컬 저장을 취소하지 않습니다.

일반 설치자는 공용 수신 서버를 열 필요가 없습니다. `basic_catalog_server_enabled`와 `basic_logo_mirror_enabled`는 기본 꺼짐입니다. 공용 서버 운영자만 조회 키(`basic_catalog_read_key`)와 제출 키(`basic_logo_submit_key`)를 각각 설정하고 필요한 수신 기능을 켭니다. 두 값은 개인 FF 공통 API 키와 달라야 하며, 서버가 같은 키 사용을 거부합니다.

별도 공용 서버 접근값은 조회 클라이언트 `TVH_M3U_REMOTE_APIKEY`로 지정할 수 있습니다. 로고 제출은 운영자가 발급한 비공개 키를 `TVH_M3U_LOGO_SUBMIT_KEY` 환경변수 또는 관리자 설정 `basic_logo_submit_key`에 지정해야 합니다. 제출 키가 없는 설치본도 로컬 아이콘 업로드는 정상 동작하고 공용 전송만 생략합니다. 두 설정에 개인 FF API 키를 넣지 마세요.

개인 API 키가 과거 공개된 설치본은 이 업데이트만으로 과거 노출이 취소되지 않습니다. 연결된 재생 클라이언트와 함께 개인 키를 교체해야 합니다.
